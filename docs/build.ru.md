# Сборка приложения

## Структура приложения

Для сборки приложения используется система сборки qmake. Поэтому приложение структурировано как
набор проектов.

* Основной проект содержит набор подпроектов.
* Подпроект [core](../core/) содержит C++ классы приложения. Они экспортируются
  в QML-контекст приложения. Они собраны в виде статической библиотеки, что облегчает их использование в модульных тестах.
  использования в unit-тестах.
* Подпроект [app](../app/) содержит код bootstrap и QML-код приложения.
* Подпроект [libs](../libs/) содержит инструменты для корректной упаковки разделяемых библиотек в RPM-пакет.
* Подпроект [qwebdavlib](../qwebdavlib/) содержит код библиотеки QWebDavLib, реализующей взаимодействие по протоколу WebDAV.
* Подпроект [catch2](../catch2/) позволяет собрать библиотеку Catch2 для управления тестами.
* Подпроект [tests](../tests/) содержит unit-тесты для приложения.

## Загрузка git подмодулей

Приложение зависит от нескольких внешних git-репозиториев

* [qwebdavlib](https://github.com/mhaller/qwebdavlib/) — библиотека QWebDAV.
* [Catch2](https://github.com/catchorg/Catch2) — библиотека unit-тестов.

Перед сборкой приложения должны быть загружены обе библиотеки:
```
git submodule init
git submodule update
```

## Сборка приложения

При создании приложения необходимо указать идентификатор клиента приложения Яндекс и секретный ключ клиента, используемый для запроса токенов авторизации. 
Зарегистрировать приложение можно, по инструкции на сайте https://yandex.ru/dev/disk/doc/dg/concepts/quickstart.html#quickstart__oauth. 
(Примечание! Укажите "Data access" как "яндекс.диск" и выберите "Доступ к Яндекс.Диску для приложений yadisk:disk").

Для сборки приложения с помощью QtCreator укажите идентификатор клиента и секретный ключ клиента в качестве параметров шага qmake (Project settings > Build > qmake > Additonal arguments)
следующим образом `"CLIENT_ID=<ваш_токен>" "CLIENT_SECRET=<ваш_токен>"`, где `<ваш_токен>` - идентификатор и секретный ключ клиента соответственно.

Для сборки приложения с помощью AppTool передайте в качестве переменных окружения идентификатор клиента и секретный ключ клиента. Это может быть сделано двумя способами:
1. Укажите эти параметры перед ключевым словом `apptool` перед началом сборки. Например:
```
CLIENT_ID=<ваш_токен> CLIENT_SECRET=<ваш_токен> apptool build
```
2. Запустите docker-образ AppTool с аргументами `--env CLIENT_ID=<ваш_токен> --env CLIENT_SECRET=<ваш_токен>`. Например:
```
docker run -it -u `id -u`:`id -g` --rm --env CLIENT_ID=<ваш_токен> --env CLIENT_SECRET=<ваш_токен> -v "$PWD":/sources -w /sources registry.omprussia.ru/omp-sdk/sdk-build-tools:dp2
```

Для сборки приложения с помощью Platform SDK передайте в качестве переменных окружения   
идентификатор клиента и секретный ключ клиента, например:     
Run Platform SDK: $PSDK_DIR/sdk-chroot  
export CLIENT_ID=c24eecb6677c4ed1a38aacc835878d0c  
export CLIENT_SECRET=df7fb0c709664470bd3f8995e34ee2cd  
mb2 -t Aurora_OS-Target build

Для сборки приложения с помощью sfdk передайте идентификатор клиента     
и секретный ключ клиента в аргументах qmake, например:               
mkdir WebDavClient_build_aarch64 && cd WebDavClient_build_aarch64     
sfdk config target=AuroraOS-Target-aarch64 , where Aurora_OS-Target-aarch64 is target name     
sfdk qmake ../WebDavClient/ CLIENT_ID=c24eecb6677c4 CLIENT_SECRET=df7fb0c709664470bd3      
sfdk make-install      
sfdk package      

## Установка приложения на устройство

Приложение упаковано в два пакета RPM. Основной пакет содержит приложение
и ресурсы. Пакет tests содержит исполняемый файл для запуска тестов.

Пакет tests не соответствует требованиям валидатора. Для того чтобы установить и запустить тесты 
на мобильное устройство, валидатор должен быть отключён.

Для проверки требований валидатора для основного приложения пакет tests должен быть удален
из списка установленных пакетов:

1. Откройте правила развертывания в приложении Qt Creator.
2. Измените шаг *RPM Deploy*. Добавьте аргумент `'-*tests*` в команду `sfdk deploy`.
